# Правила для ИИ-агентов (Claude, ChatGPT / Codex)

Это закрытый репозиторий данных инженерных проектов ООО «ИГНИС». Владелец и единственный, кто принимает изменения, — **Дмитрий**. Вы — **Claude** или **ChatGPT**. Все тексты для человека (названия, примечания, описания PR) пишите **по-русски**. Ключи JSON, пути и значения перечислений — **ровно как ниже**.

Источник истины по схеме — `tools/model.js` (функции `validateProject`, `validateFile`, `validateChatMessage`, `chatFileName`, `validFilePath`, `approvalChanges`, перечисления). Если этот документ и `model.js` расходятся — прав `model.js`. Не изменяйте `tools/` и `.github/` без прямой просьбы Дмитрия.

---

## 1. Перед началом работы

1. Прочитайте **последние ~40 сообщений чата проекта** (`projects/<slug>/chat/`, файлы по имени отсортированы по времени) — там текущие договорённости, вопросы к вам и ответы другого ИИ.
2. Прочитайте `projects/<slug>/project.json` — название, статус, описание.
3. Прочитайте `tasks.json`: открытые задачи (`status` ≠ `"Готово"`) с `assignee` = ваше имя (`"Claude"` или `"ChatGPT"`), и последние записи в `decisions` — не противоречьте принятым решениям без обоснования.
4. Посмотрите открытые pull request'ы (`gh pr list`) — не трогайте проект, который уже правит другой PR, или согласуйте изменения в его описании.
5. Посмотрите `documents.json`, `sources.json`, `cost.json`, если задача их касается.

## 2. Порядок внесения изменений

- **НИКОГДА не коммитьте в `main`** и не сливайте PR сами. Единственное исключение — **добавление новых сообщений чата**, см. раздел 9.
- Ветка: `ai/claude/<короткая-тема>` или `ai/chatgpt/<короткая-тема>` (латиница, дефис), например `ai/claude/raskroy-ograzhdenie`.
- Каждое сообщение коммита начинается с `[Claude]` или `[ChatGPT]`: `[Claude] Раскрой трубы для ограждения Ø3000`.
- Откройте pull request в `main`. Заголовок PR **обязательно** начинается с `[Claude]` или `[ChatGPT]`.
- Описание PR:
  - **Что изменено** — файлы и суть;
  - **Почему** — какая задача (`t-…`) или просьба;
  - **Источники и допущения** — откуда цифры, что принято без проверки;
  - **Открытые вопросы** — что должен решить Дмитрий.
- Один PR = одно связное изменение, желательно в одном проекте.
- Открыв PR, напишите в чат проекта сообщение: «Предложение #N: <суть>» (N — номер PR), чтобы Дмитрий и другой ИИ его увидели.
- Перед открытием PR выполните `node tools/validate.mjs` — проверка должна пройти. Та же проверка автоматически запускается в GitHub Actions.

## 3. Запреты и обязательные правила

- **Никогда не ставьте и не снимайте статус `"Разрешено к выдаче"`** у редакции документа, не удаляйте такие редакции и проекты с ними. Проверка в CI отклоняет PR с любым таким изменением. Новые редакции создавайте со статусом `"Не проверено"` (или `"На проверке"`, если просите Дмитрия проверить).
- Не удаляйте файлы, документы, задачи, источники и строки других авторов без прямой просьбы.
- **Сохраняйте существующие id.** Новые id: префикс + дефис + 6…40 символов `[a-z0-9]`, например 12 случайных hex-символов: `d-4b8e1f6a90c2`. id уникален внутри файла; не используйте повторно удалённые id.
- В полях `author` (project, редакции, задачи, решения) и `origin` (источники) пишите `"Claude"` или `"ChatGPT"` — то, кем вы являетесь. Существующие значения других авторов не меняйте.
- Задачи для ИИ: `assignee` = `"Claude"` или `"ChatGPT"`; для человека — `"Дмитрий"`. Закончив свою задачу, ставьте `"status": "Готово"` и кратко пишите итог в `note`.
- Значимые инженерные решения (материал, сортамент, способ соединения, технология, допуски, отказ от варианта) записывайте в `tasks.json` → `decisions`: кратко в `title`, обоснование в `text`.
- При правке проекта обновляйте `project.json` → `updated` (сегодняшняя дата).
- Даты — строго `ГГГГ-ММ-ДД`. В каждом файле `"schema": 1`.
- Никаких секретов: пароли, токены, ключи API, паспортные и банковские данные.

## 4. Структура

```
projects/<slug>/
  project.json
  documents.json
  tasks.json
  sources.json
  cost.json
  chat/
    <ГГГГММДДTЧЧММССZ>-<автор>-<m-id>.json   одно сообщение чата = один файл
  files/
    docs/<id редакции>-<safe-name>.<ext>      файлы редакций документов (r-…)
    sources/<id источника>-<safe-name>.<ext>  файлы исходных данных (s-…)
    chat/<id сообщения>-<safe-name>.<ext>     вложения сообщений чата (m-…)
    work/<safe-name>.<ext>                    рабочие файлы участников
```

- `<slug>` — имя папки: латиница в нижнем регистре, цифры, дефис (`^[a-z0-9][a-z0-9-]{0,60}$`). Пример: `ograzhdenie-d3000`. Транслитерация как в `slugify()` из `model.js`.
- `<safe-name>` — транслит имени файла, только `[a-z0-9._-]`, как `safeFileName()` из `model.js`. Расширение в нижнем регистре.
- В корне папки проекта — **только** пять JSON-файлов и папки `chat/`, `files/`. Ничего больше (никаких README, заметок, временных файлов).
- Все пять файлов обязательны, даже если списки пустые.

## 5. Файлы JSON — полные примеры

### project.json

```json
{
  "schema": 1,
  "id": "p-7f3a9c2e41b0",
  "name": "Ограждение Ø3000",
  "status": "В работе",
  "customer": "ГБУ «Жилищник»",
  "description": "Кольцевое ограждение вокруг ели, труба 40×20×2.",
  "created": "2026-11-09",
  "updated": "2026-11-09",
  "author": "Дмитрий"
}
```

Обязательные: `schema`, `id` (`p-…`), `name` (до 200 символов), `status`, `created`, `updated`. `status`: `"Идея"`, `"В работе"`, `"Пауза"`, `"Сдан"`, `"Архив"`.

### documents.json

```json
{
  "schema": 1,
  "documents": [
    {
      "id": "d-4b8e1f6a90c2",
      "name": "Ограждение Ø3000 — сборочный чертёж",
      "format": "PDF",
      "revisions": [
        {
          "id": "r-a1c5e9d3b7f4",
          "rev": "R01",
          "status": "Не проверено",
          "date": "2026-11-09",
          "author": "Claude",
          "note": "Первая редакция.",
          "file": {
            "path": "projects/ograzhdenie-d3000/files/docs/r-a1c5e9d3b7f4-sborochnyy-chertezh.pdf",
            "name": "Сборочный чертёж.pdf",
            "size": 248133,
            "sha256": "9f2c…64 hex-символа…"
          }
        }
      ]
    }
  ]
}
```

- Документ: `id` (`d-…`), `name`, `format`, `revisions` (список, можно пустой).
- `format`: `"PDF"`, `"DWG"`, `"DXF"`, `"STEP"`, `"SLDPRT"`, `"STL"`, `"XLSX"`, `"Фото"`, `"Другое"`.
- Редакция: `id` (`r-…`), `rev` (`R01`, `R02`… — не повторяется в пределах документа), `status`, `date`, `author`; необязательно `note`, `file`.
- `status` редакции: `"Не проверено"`, `"На проверке"`, `"Разрешено к выдаче"` (**только Дмитрий**), `"Архив"`. «Разрешено к выдаче» — не более одной редакции на документ.
- Новая версия чертежа = **новая редакция** (новый `id`, следующий `rev`), старые не перезаписывайте.
- `file`: `path` (полный путь от корня репозитория, обязательно внутри `projects/<slug>/files/docs/`), `name` (исходное имя), `size` (байты, должен совпадать с файлом), `sha256` (необязательно, 64 строчных hex; если указан — должен совпадать). Без файла поле `file` не пишите.

## 6. Себестоимость (cost.json)

- `currency` — всегда `"RUB"`. Деньги — **в рублях числом** (`95`, `1250.5`), не строкой и не в копейках.
- `price` — цена **за единицу** (`unit`) **без НДС**, если в `note` не сказано иное.
- Сумма строки = `qty × price`; итог считает приложение: сумма строк + `overheadPct` % накладных, затем + `marginPct` % наценки. Итоги в файл не пишите.
- `group`:
  - `"Материалы"` — металл, краска, крепёж россыпью, расходники (`кг`, `м`, `м²`, `лист`, `шт`);
  - `"Покупное"` — готовые изделия: светильники, блоки питания, замки, опоры (`шт`, `компл`);
  - `"Работы"` — резка, гибка, сварка, ЧПУ, покраска, монтаж, доставка (`ч`, `м²`, `рейс`, `компл`);
  - `"Прочее"` — всё остальное.
- `unit` — короткая единица до 20 символов: `кг`, `м`, `м²`, `шт`, `ч`, `лист`, `компл`, `рейс`.
- `qty`, `price` — числа ≥ 0.
- В `note` **указывайте источник цены** (поставщик / сайт / прайс и дату) и расчёт количества. Если цена не проверена — начинайте `note` словами `«Ориентировочно, проверить»`. Не выдумывайте точные цены, выдавая их за проверенные.

## 7. Файлы

- Все файлы, кроме JSON проекта и сообщений чата, — **только** в `projects/<slug>/files/<docs|sources|chat|work>/`, без подпапок. Имя — только `[a-z0-9._-]`.
  - `docs/<id редакции>-<safe-name>.<ext>` — упомянут в `documents.json` (`revisions[].file`);
  - `sources/<id источника>-<safe-name>.<ext>` — упомянут в `sources.json` (`sources[].file`);
  - `chat/<id сообщения>-<safe-name>.<ext>` — вложение, упомянут в `files` сообщения чата;
  - `work/<safe-name>.<ext>` — **рабочие файлы**: расчёты, черновики, скрипты, текстовые заметки, DXF и т.п., ещё не зарегистрированные как документы. Упоминать их не обязательно. Когда рабочий файл становится документом — создайте редакцию и положите копию в `docs/`.
- Максимум **50 МБ** на файл. Крупные модели — архивируйте или давайте ссылку (`url`).
- Указывайте точный `size` в байтах; `sha256` желателен (`sha256sum файл`).
- Не коммитьте секреты, `.env`, ключи, личные данные.

## 8. Проверка

```
node tools/validate.mjs
```

Проверяет: схему всех пяти файлов каждого проекта (`validateProject`), каждое сообщение `chat/*.json` (`validateChatMessage`) и что имя файла равно `chatFileName(msg)`, имена папок и файлов, лишнее в корне проекта и в `files/`, повтор `id` проекта между папками и `id` сообщений, наличие файлов по `file.path`, совпадение `size` и `sha256`. В PR дополнительно (`--base`) — что отметка «Разрешено к выдаче» не изменилась (`approvalChanges`) и что существующие сообщения чата и вложения `files/chat/` не изменены и не удалены. Ошибка — выход с кодом 1; успех — «Проверка пройдена: N проектов».

## 9. Чат проекта

Чат — **главное место общения троих**: Дмитрий, Claude, ChatGPT. Вопросы, договорённости, «кто что делает», ссылки на предложения — всё здесь.

**Формат.** Каждое сообщение — отдельный файл `projects/<slug>/chat/<имя>.json`, где имя = `chatFileName(msg)` = `<date без «-», «:» и долей секунды>-<транслит автора>-<id>.json`, например `20261109T094025Z-claude-m-8f1d3b6e0a92.json`.

```json
{
  "schema": 1,
  "id": "m-8f1d3b6e0a92",
  "author": "Claude",
  "date": "2026-11-09T09:40:25Z",
  "replyTo": "m-2c7e9a1f4b06",
  "mentions": ["ChatGPT", "Дмитрий"],
  "text": "Беру раскрой. @ChatGPT ориентируйся на 80 кг трубы.",
  "files": [
    {
      "path": "projects/ograzhdenie-d3000/files/chat/m-8f1d3b6e0a92-raskroy.xlsx",
      "name": "Раскрой.xlsx",
      "size": 18342,
      "sha256": "…64 hex-символа…"
    }
  ]
}
```

- `id` — `m-` + 6…40 `[a-z0-9]`; `author` — `"Claude"` или `"ChatGPT"`; `date` — **текущее время UTC** в ISO: `ГГГГ-ММ-ДДTЧЧ:ММ:ССZ` (можно с миллисекундами).
- `text` — по-русски, до 20 000 символов; обязателен, если нет `files`.
- `replyTo` — `id` сообщения, на которое отвечаете (указывайте всегда, когда отвечаете).
- `mentions` — к кому обращаетесь: `"Claude"`, `"ChatGPT"`, `"Дмитрий"`. В тексте пишите `@Claude`, `@ChatGPT`, `@Дмитрий`.
- `files` — до 20 вложений. Новое вложение кладите в `files/chat/<id сообщения>-<safe-name>.<ext>`; можно ссылаться и на уже существующие файлы `docs/`, `sources/`, `work/`.
- **Сообщения только добавляются.** Не изменяйте и не удаляйте существующие файлы `chat/` и `files/chat/` (свои тоже) — CI отклонит. Чтобы исправиться, напишите новое сообщение.

**Как коммитить.**
- **Исключение из правила «не коммитить в `main`»:** ИИ **может** коммитить напрямую в `main` **только добавление новых файлов** в `projects/*/chat/` и `projects/*/files/chat/` (сообщение и его вложения). Сообщение коммита начинается с `[Claude]` или `[ChatGPT]`, например `[Claude] Чат: ответ по раскрою`. В такой коммит больше ничего не включайте.
- Всё остальное (JSON проекта, `docs/`, `sources/`, `work/`) — **только через ветку и PR**, а в чат — сообщение со ссылкой «Предложение #N».
- Если вы не можете писать в `main` (например, ChatGPT через коннектор или Codex умеет только PR) — положите файл сообщения в тот же PR. Приложение покажет его в чате как ожидающее, пока Дмитрий не сольёт PR.
- Перед коммитом выполните `node tools/validate.mjs`.

**Режимы работы.**
- **Ручной.** Дмитрий пишет вам в Claude или ChatGPT: «проверь чат проекта X». Вы читаете репозиторий `rrrig/ignis-projects` (раздел 1), отвечаете на новые сообщения, адресованные вам (`mentions` или `@Имя`), и выполняете задачи по правилам этого документа.
- **Автоматический.** Бот GitHub Actions отвечает в чат, когда в сообщении есть `@Claude` / `@ChatGPT`. Он работает по этим же правилам; устройство описано в `docs/AI-BOT.md`.

## 10. Совместная работа Claude и ChatGPT

- **Читайте сообщения друг друга** и учитывайте их: не пересчитывайте заново то, что другой ИИ уже посчитал, — ссылайтесь на его сообщение (`replyTo`) и при необходимости уточняйте.
- **Явно отвечайте на вопросы другого ИИ** — отдельным сообщением с `replyTo` и `mentions`.
- **Не дублируйте работу.** Смотрите `assignee` в `tasks.json` и открытые PR. Чужую задачу не берите; если она блокирует вас — спросите в чате.
- **Договаривайтесь в чате, кто что делает**, прежде чем браться за общую задачу: «Беру раскрой, @ChatGPT — цены». Новую задачу для другого ИИ можно предложить в PR (`tasks.json`, `assignee` = его имя).
- **При разногласии** не спорьте в PR'ах правками друг друга.
