# Правила работы ИИ с хранилищем ИГНИС ПРО на GitHub

Документ для **ChatGPT** (и Claude). Прочитать полностью перед любой работой с репозиториями. Цель — совместная работа над инженерными проектами ООО «ИГНИС» **без нарушения правил GitHub**, чтобы аккаунт `rrrig` больше не блокировали.

Владелец и единственный, кто принимает решения и изменения, — **Дмитрий**.

Правила формата данных (схема JSON, структура папок, чат, себестоимость) — в файле **`AGENTS.md`** в корне хранилища. Этот документ его **дополняет** правилами безопасности аккаунта. При расхождении по формату данных прав `AGENTS.md` / `tools/model.js`; по безопасности — этот документ.

## 1. Правила GitHub, которые нельзя нарушать

Основание: GitHub Acceptable Use Policies и GitHub Terms for Additional Products and Features (раздел Actions).

### 1.1. GitHub Actions — только проверка данных
- **Запрещено** запускать в GitHub Actions ботов, чат-ответчики, вызовы API ИИ (OpenAI, Anthropic и т.п.), «серверные приложения», раздачу файлов. GitHub разрешает Actions только для сборки, тестирования, развёртывания и публикации проекта.
- Разрешён только существующий сценарий проверки данных `validate.yml`.
- **Бот `ai-chat.yml` не используется.** Не создавать, не восстанавливать, не включать его и аналоги.
- Не добавлять workflow с расписанием (`schedule`/cron), бесконечными циклами, массовыми запусками.
- Папки `.github/` и `tools/` не изменять без прямой просьбы Дмитрия.

### 1.2. Никакой массовой автоматики
- Работать **только по просьбе Дмитрия**, в рамках одного сеанса. Никаких фоновых процессов, расписаний, опроса репозитория по таймеру.
- Не делать массовых операций: десятки PR, сотни коммитов, пакетное создание issues/комментариев.
- Ориентир на сеанс: **не больше 5–10 коммитов и 1–3 PR**. Связанные изменения — одним коммитом.
- Лимиты API GitHub (не приближаться): 5000 запросов в час на аккаунт; для создающих запросов (коммиты, PR, комментарии) — не больше 80 в минуту и 500 в час. При ответе 403/429 «rate limit» — **остановиться**, не повторять в цикле, сообщить Дмитрию.
- Запрещено: автоматически ставить звёзды, подписываться, создавать дополнительные аккаунты, выдавать себя за другого.

### 1.3. Объём файлов
- Файл — **не больше 50 МБ** (GitHub предупреждает с 50 МБ и отклоняет файлы больше 100 МБ).
- Весь репозиторий желательно держать **до 1 ГБ** (GitHub рекомендует до 1 ГБ, настоятельно — до 5 ГБ).
- Крупные 3D-модели, видео, фотоархивы — архивировать, уменьшать или хранить **ссылкой** (`url` в `sources.json`).
- Не загружать одно и то же повторно; новая редакция — только если содержимое изменилось.
- Не хранить сгенерированный мусор: временные файлы, кэши, `node_modules`, дубликаты.

### 1.4. Безопасность и данные
- **Никогда** не записывать в репозиторий токены, пароли, ключи API, паспортные и банковские данные, личные данные сотрудников.
- Токен Дмитрия хранится только на его телефоне — не просить его прислать в чат.
- Не публиковать содержимое приватного хранилища в публичный `RRR-demo` или куда-либо ещё.
- Не загружать чужие материалы, на которые нет прав (платные модели, чужие чертежи с запретом распространения).

## 2. Порядок работы

1. **Прочитать** чат проекта (последние ~40 сообщений), `project.json`, `tasks.json`, открытые PR.
2. **Договориться в чате**, кто что делает (см. раздел 4).
3. **Изменения — только через ветку и Pull Request:**
   - ветка `ai/chatgpt/<тема>` (у Claude — `ai/claude/<тема>`), латиница и дефис;
   - коммиты и заголовок PR начинаются с `[ChatGPT]` / `[Claude]`;
   - в описании PR: **Что изменено · Почему · Источники и допущения · Открытые вопросы**;
   - один PR = одно связное изменение в одном проекте.
4. **Никогда** не коммитить в `main` и не сливать PR самостоятельно. Единственное исключение — добавление **новых** сообщений чата (`projects/*/chat/`, `projects/*/files/chat/`). Если нет права писать в `main` — положить сообщение в PR.
5. Перед PR выполнить `node tools/validate.mjs` — проверка должна пройти.
6. После открытия PR написать в чат проекта: «Предложение #N: суть».
7. Принимает, отклоняет и ставит «Разрешено к выдаче» **только Дмитрий**.

### Нельзя
- Ставить или снимать статус «Разрешено к выдаче», удалять такие редакции.
- Удалять или переписывать чужие файлы, задачи, решения, строки сметы, сообщения чата (свои сообщения тоже — только новое сообщение-исправление).
- Перезаписывать старые редакции чертежей — новая версия = новая редакция (`R02`, `R03`…).
- Менять существующие `id`.

## 3. Качество инженерной работы

- **Точность в мелочах.** Размеры с единицами, сортамент по ГОСТ, масса, количество. Перепроверять расчёты перед отправкой.
- **Не выдумывать.** Непроверенная цена или размер — с пометкой «Ориентировочно, проверить» и источником.
- В каждом решении учитывать: **себестоимость**, **простоту изготовления** (оборудование цеха: фрезер ЧПУ 4000×2000, ArtCAM 2018; сварка, гибка), **внешний вид**, при необходимости прочность и сроки.
- Значимые решения (материал, соединение, технология, отказ от варианта) записывать в `tasks.json` → `decisions` с обоснованием.
- Все тексты для человека — **по-русски**.

## 4. Совместная работа ChatGPT и Claude

- Читать сообщения друг друга, не пересчитывать заново то, что уже посчитано другим, — ссылаться (`replyTo`).
- Не брать чужие задачи (`assignee`) и не править проект, который уже меняет открытый PR другого ИИ.
- Перед общей задачей договориться в чате: «Беру раскрой, @Claude — смета».
- При разногласии **не спорить правками**. Написать Дмитрию (`@Дмитрий`) оба варианта с плюсами и минусами по себестоимости, технологичности и внешнему виду. Решает Дмитрий.
- Ответы в чат — **вручную**, когда Дмитрий просит («проверь чат проекта X»), а не автоматически.

## 5. Если что-то пошло не так

- Ошибка доступа, лимита или проверки — остановиться, не повторять попытки в цикле, описать Дмитрию, что произошло.
- Предупреждение или письмо от GitHub — прекратить любые действия с репозиторием и сообщить Дмитрию.
- Сомнение, разрешено ли действие, — спросить Дмитрия до выполнения.
