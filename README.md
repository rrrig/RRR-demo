# ИГНИС ПРО / RRR

Инженерный архив **R08** работает по прежнему адресу `r05/` и использует прежнее имя базы `rrr-r05-archive`. Корневая страница остаётся каталогом R04.1. Данные находятся в этом браузере и режиме запуска на устройстве; сервера данных, облачного хранения и общей синхронизации нет.

## Что изменено в R08

Каталог и содержимое документов хранятся отдельно. Вложения разбиты на блоки до 4 МиБ; переименование проекта, открытие списка и другие изменения метаданных не считывают и не переписывают весь архив. Текущий и предыдущий снимки ссылаются на неизменяемые блоки. Для разрешения выдачи и скачивания содержимое проверяется по SHA-256; контрольная сумма проверяет целостность, а не авторство документа.

Пределы приложения: **100 МиБ на один файл**, **5 ГиБ активных вложений**, **50 файлов в одном пакете прикрепления**. Это программные ограничения, а не обещание доступного места на конкретном телефоне. Квота и использование сайта в разделе копии — оценка браузера, а не свободное место всего устройства. Фактическая запись может завершиться ошибкой нехватки места. [Политика хранения WebKit](https://webkit.org/blog/14403/updates-to-storage-policy/).

Большую резервную копию можно сохранить комплектом: JSON-оглавление и пронумерованные части примерно по 32 МиБ. Части объединяют блоки нескольких файлов, поэтому небольшой архив не требует отдельного скачивания для каждого документа. Подготовка и проверка идут последовательно, без сборки всех вложений в один объект в памяти.

## Обновление с R07

1. Сохранить внешнюю полную копию из рабочей версии.
2. Закрыть старые вкладки и открыть обновление в том же браузере или запуске с домашнего экрана, где находятся проекты.
3. Дождаться открытия каталога. Текущий архив и предыдущий снимок автоматически переносятся в новый формат с проверкой вложений. Названия, идентификаторы, источники, сопоставления каталога и журнал сохраняются.
4. Проверить несколько проектов и вложений, затем сохранить новую внешнюю копию.

Старая запись удаляется только при успешном переключении на подготовленные данные. При подтверждённой ошибке подготовки или переключения исходные данные остаются на месте. Если браузер сообщает неопределённый результат записи, приложение блокирует следующие изменения до перечитывания фактического состояния. Старые версии приложения не могут записывать в обновлённую базу; повторное открытие старой страницы не является способом отката.

Не очищать данные браузера и не удалять рабочий запуск приложения без проверенной внешней копии. Safari и запуск с домашнего экрана могут иметь разные области данных. Service worker и гарантированный офлайн-запуск не добавлены.

## Резервные копии

Для большой копии подготовить комплект в разделе «Копия», сохранить оглавление и **все** перечисленные части в одну папку. Нажатие кнопки скачивания не подтверждает, что файл сохранён в «Файлах»: это нужно проверить самостоятельно. Не смешивать комплекты. Если iPhone добавит номер к имени скачанного файла, часть всё равно распознаётся по внутреннему заголовку. Один JSON без частей не содержит вложений.

Для восстановления выбрать оглавление и все части одного комплекта. Приложение проверяет состав, размеры, связи, контрольные суммы частей и файлов. Данные готовятся отдельно; текущий каталог заменяется только после полной проверки, одной завершающей транзакцией. Отсутствующая часть, повреждение, конфликт с другой вкладкой или подтверждённая отмена не дают частичного восстановленного архива. После прерывания можно заново выбрать тот же комплект.

Прежний формат одной полной JSON-копии сохранён для небольших архивов: до 80 МиБ самого JSON. Копии схем 1 и 2 принимаются. Для большого архива приложение предлагает комплект частями вместо сборки огромного base64-JSON. Новые копии схемы 3 не предназначены для старых версий приложения.

Перед восстановлением, удалением, успешным пакетом прикрепления или изменяющим импортом каталога сохраняется **один** предыдущий снимок. «Вернуть предыдущее состояние» заменяет весь текущий архив, включая изменения после снимка. Следующая такая операция заменяет этот снимок. Это не отдельная корзина и не история всех версий резервных копий. Вложения, на которые ссылается предыдущий снимок или ещё используемый комплект экспорта, продолжают занимать место.

## Проекты, документы и исходники

Проекты и документы можно переименовывать и удалять. Удаление проекта затрагивает его документы, редакции и локальные вложения; удаление документа — его редакции и вложения. Подтверждение показывает состав удаления. Исходники в ChatGPT не удаляются. Повторный импорт каталога может снова добавить удалённые карточки.

Одна редакция содержит один неизменяемый файл. Чтобы изменить содержимое, создайте новую редакцию. Статус «Разрешено к выдаче» — отметка пользователя, которая не заменяет инженерную проверку; только одна редакция документа может иметь эту отметку.

В «Документах» пакетное прикрепление предлагает редакцию при единственном совпадении исходного имени (Unicode NFC, с учётом регистра) и размера. Это подсказка, а не подтверждение содержимого. Неоднозначные назначения нужно выбрать вручную или явно пропустить. Занятые редакции не перезаписываются, два файла одной редакции не назначаются. Подготовка пакета последовательная; в текущем архиве появляется весь успешный пакет сразу.

Карточка исходника содержит метаданные, а не сам файл. Прямые ссылки на скачивание ChatGPT из внешнего приложения не используются. Сначала сохраните исходник из ChatGPT на устройство, затем прикрепите его к редакции. Проектные файлы и частный каталог не входят в публичный репозиторий.

## Проверки

Node.js 22 или новее:

```sh
npm install
npm test
```

Автоматические проверки используют Node Web Crypto, fake-indexeddb и jsdom. Они проверяют логику хранения, совместимость и интерфейс, но не заменяют проверку реальных ограничений Safari, системного выбора и сохранения файлов на iPhone. Для приёмки на устройстве проверить сохранение после закрытия, открытие вложения, комплект копии и его восстановление в отдельном тестовом браузере или профиле.

Подробности формата и миграции приведены в [r05/README.md](r05/README.md).
